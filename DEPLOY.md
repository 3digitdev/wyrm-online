# Deploying WyrmOnline to Google Cloud Run

## Prerequisites

- [Google Cloud CLI](https://cloud.google.com/sdk/docs/install) installed and authenticated
- A GCP project with billing enabled
- Docker (only needed for local builds)

## One-time GCP setup

### 1. Create a GCP project

```bash
gcloud projects create wyrm-online --name="WyrmOnline"
```

### 2. Link a billing account

```bash
gcloud billing accounts list
gcloud billing projects link wyrm-online --billing-account=YOUR_BILLING_ACCOUNT_ID
```

### 3. Enable required APIs

Cloud Build builds the Docker image, Artifact Registry stores it, Cloud Run hosts it:

```bash
gcloud services enable \
  cloudbuild.googleapis.com \
  run.googleapis.com \
  artifactregistry.googleapis.com \
  --project=wyrm-online
```

### 4. Create an Artifact Registry repo

Artifact Registry is where the built Docker image lives. Cloud Run pulls from here.

```bash
gcloud artifacts repositories create wyrm-online \
  --repository-format=docker \
  --location=us-central1 \
  --project=wyrm-online
```

### 5. Generate a secret key

Phoenix uses this to sign cookies and sessions:

```bash
mix phx.gen.secret
```

Save the output — you'll pass it as an env var during deploy.

## Deploy

This single command builds the Docker image via Cloud Build, pushes it to
Artifact Registry, and deploys it to Cloud Run:

```bash
gcloud run deploy wyrm-online \
  --source . \
  --project=wyrm-online \
  --region=us-central1 \
  --set-env-vars SECRET_KEY_BASE=<your-secret>,PHX_HOST=<your-domain-or-run-url> \
  --port 4000 \
  --min-instances 1 \
  --allow-unauthenticated
```

### What each flag does

| Flag | Purpose |
|------|---------|
| `--source .` | Build from the Dockerfile in the current directory |
| `--region` | GCP region to deploy to |
| `--set-env-vars` | `SECRET_KEY_BASE` for Phoenix crypto, `PHX_HOST` for URL generation |
| `--port 4000` | The port Phoenix listens on inside the container |
| `--min-instances 1` | Keeps one instance always running (game state is in-memory, scale-to-zero kills it) |
| `--allow-unauthenticated` | Makes the service publicly accessible |

## After first deploy

Cloud Run assigns a URL. After the first deploy, update `PHX_HOST` to match
the actual URL (without `https://`):

```bash
gcloud run services update wyrm-online \
  --project=wyrm-online \
  --region=us-central1 \
  --set-env-vars "SECRET_KEY_BASE=<your-secret>,PHX_HOST=<your-service-url>.run.app"
```

### Custom domain

```bash
gcloud run domain-mappings create \
  --service=wyrm-online \
  --domain=your-domain.com \
  --region=us-central1
```

Then add the DNS records it tells you to.

## Redeploying

```bash
gcloud run deploy wyrm-online --source . --project=wyrm-online --region=us-central1
```

Cloud Build rebuilds the image and Cloud Run does a zero-downtime rolling update.
Env vars persist across deploys — no need to pass them again.

**Note:** Redeploying kills in-progress games since state is in-memory.

## How the Dockerfile works

Generated by `mix phx.gen.release --docker --no-ecto`. Multi-stage build:

1. **Builder stage** — installs Elixir/Erlang, compiles deps, builds assets
   (Tailwind, esbuild), creates a Mix release (self-contained binary bundle)
2. **Runner stage** — slim Debian image with just the compiled release, no
   Elixir/Erlang runtime needed

The release is started by `rel/overlays/bin/server` which sets `PHX_SERVER=true`
so Phoenix binds to the network.
